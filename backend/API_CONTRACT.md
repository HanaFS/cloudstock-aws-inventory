# CloudStock API contract

This implementation follows the field names and function ownership from the
Cloud owner's architecture document. The request details below fill gaps that
document leaves unspecified; confirm them with the Cloud owner before wiring
the functions to the already-existing AWS resources.

## Conventions and authorization

- Success: `{"success": true, "data": ...}`. Error:
  `{"success": false, "message": "...", "code": "..."}`.
- List responses return `data` as an array and include `nextToken` when another
  page exists. `limit` is 1–100 (default 100), except Cognito users are capped
  at 60 per Cognito API limit.
- `GET /health` is public. Other APIs require Cognito `Admin` or `Staff`.
  `GET|POST|PUT|DELETE /users` routes and `GET /logs` require `Admin`.
- `POST /transactions` requires `Idempotency-Key` (1–128 characters).
- Local adapter auth accepts only `Bearer local-dev:Admin` or
  `Bearer local-dev:Staff`.

## Routes

| Method and path | Behavior |
| --- | --- |
| `GET /health` | Public health check. |
| `GET /products` | List; supports `filter=low-stock`, `limit`, `nextToken`. |
| `POST /products` | Create product. |
| `GET /products/{productId}` | Read product. |
| `PUT /products/{productId}` | Update product; omitted fields retain current values. |
| `DELETE /products/{productId}` | Delete only without transaction history. |
| `GET /suppliers` | List suppliers with pagination. |
| `POST /suppliers` | Create supplier. |
| `GET /suppliers/{supplierId}` | Read supplier. |
| `PUT /suppliers/{supplierId}` | Update supplier. |
| `DELETE /suppliers/{supplierId}` | Delete only when unused and without history. |
| `GET /transactions` | List in `createdAt` order. |
| `POST /transactions` | Write transaction and stock update atomically. |
| `GET /transactions/{transactionId}` | Read transaction. |
| `GET /dashboard`, `GET /dashboard/stats` | Aggregate inventory and today's transaction totals. |
| `GET /users` | List Cognito users; supports pagination. |
| `POST /users` | Create Cognito user and assign `Admin` or `Staff` group. Cognito emails the temporary password. |
| `GET /users/{userId}` | Read user by Cognito username or `sub`. |
| `PUT /users/{userId}` | Update email/name, group role, or enabled status. |
| `DELETE /users/{userId}` | Delete Cognito user; self-delete is denied. |
| `POST /users/{userId}/reset-password` | Ask Cognito to send a password-reset email. |
| `GET /logs` | Read configured CloudWatch Lambda log groups; defaults to the last 7 days. |
| `POST /products/upload-url` | Create presigned POST for a product image. |
| `POST /transactions/invoice-upload-url` | Create presigned POST for a private invoice. |
| `GET /transactions/{transactionId}/invoice-url` | Create a short-lived URL for the stored invoice. |

Presigned upload responses include `url`, `fields`, `objectKey`, an
`imageUrl` (product image) or `invoiceUrl` (invoice key), and `expiresIn`.
Clients must POST a `FormData` body containing every returned field plus the
file. Upload credentials are short lived (300 seconds). Image uploads allow
JPEG/PNG/WebP up to 5 MB; invoices allow PDF/JPEG/PNG up to 15 MB.

Product images are publicly readable under `products/`. Invoice objects remain
private under `invoices/`; the `invoiceUrl` transaction attribute stores the
stable S3 key, never a presigned URL. Authorized users obtain a temporary read
URL through the invoice route.

The current frontend does not call either upload-url route: product create and
update reject an attached image before sending the request, and transaction
create rejects an attached invoice before sending it. The routes are available
for a future frontend integration, but these upload flows cannot be completed
without changing the frontend.

## Frontend API fields and DynamoDB storage

### Products

| Field | Contract |
| --- | --- |
| `productId` | Partition key; caller-supplied ID. |
| `name`, `category` | Required non-empty strings. |
| `price` | Non-negative integer. |
| `quantity` | Non-negative integer in frontend requests/responses; stored as `stockQuantity` in DynamoDB. |
| `minThreshold` | Non-negative integer. |
| `imageUrl` | Public HTTPS URL or omitted. Image upload from the current frontend is not yet connected. |
| `updatedAt` | UTC ISO-8601 time generated by API. |

The backend derives its internal `status` from stored stock on every
create/update. `filter=low-stock` uses `stockQuantity < minThreshold`.

### Suppliers

`supplierId` is the partition key. Other attributes are `name`, `phone`, and
`address`.

### Users

The frontend API uses `status=ACTIVE|LOCKED`. `LOCKED` maps to a disabled
Cognito user; `DISABLED` remains an internal Cognito state, not the frontend
contract.

### Transactions

| Field | Contract |
| --- | --- |
| `transactionId` | Partition key; generated from authenticated subject and idempotency key. |
| `timestamp` | UTC ISO-8601 time returned to the frontend; stored as `createdAt` in DynamoDB. |
| `type` | `IN` or `OUT` in the frontend API; stored as `IMPORT` or `EXPORT` in DynamoDB. |
| `productId`, `productName` | Product ID and name snapshot. |
| `amount` | Positive integer stock delta in frontend requests/responses; stored as `quantity` in DynamoDB. |
| `performedBy` | Authenticated Cognito username; never client supplied. |
| `supplierId`, `invoiceUrl` | Optional on `IN`; stored as an `invoices/...` key. |
| `reason` | Required for `OUT`; optional on `IN`. |

The table stores composite key (`transactionId`, `createdAt`) and defines a
`ByCreatedAt` GSI with `gsi1pk` constant `TRANSACTION` and `gsi1sk` =
`createdAt#transactionId` to support global, chronological list operations.
The existing Cloud table must have the index before these handlers can list
transactions.

The stock update and transaction item are written with DynamoDB
`TransactWriteItems`. The stock condition also checks the observed quantity so
the derived status cannot go stale under concurrent writes. Conflicts return
`409 TRANSACTION_CONFLICT`; retry with the same idempotency key. Reusing the
same key with a different body returns `409 IDEMPOTENCY_KEY_REUSED`.

## Lambda environment and ownership

| Function module | Routes | Required environment / permissions |
| --- | --- | --- |
| `src.users.handler` | `/users` | `USER_POOL_ID`; Cognito Admin user/group operations. |
| `src.dashboard.handler` | `/dashboard` | `TABLE_PRODUCTS`, `TABLE_SUPPLIERS`, `TABLE_TRANSACTIONS`; DynamoDB Scan. |
| `src.catalog.handler` | `/products`, `/suppliers`, image presign | `TABLE_PRODUCTS`, `TABLE_SUPPLIERS`, `TABLE_TRANSACTIONS`, `BUCKET_NAME`; DynamoDB CRUD/Scan and S3 PutObject on `products/*`. |
| `src.transactions.handler` | `/transactions`, `/logs`, invoice presign/read | `TABLE_TRANSACTIONS`, `TABLE_PRODUCTS`, `TABLE_SUPPLIERS`, `BUCKET_NAME`, `LOG_GROUPS`; DynamoDB transaction/query, S3 invoice access, CloudWatch FilterLogEvents. |

`LOG_GROUPS` is a comma-separated allowlist of up to 50 CloudWatch log group
names. The handler never lists arbitrary groups from request input. AWS
credentials and real infrastructure endpoints are not configured in source
code.

## Integration boundary and open infrastructure items

`backend/template.yaml` is a standalone development stack that creates its
own API Gateway, Cognito pool, DynamoDB tables, and S3 bucket. It does not
attach to the Cloud owner's pre-existing API Gateway, pool, tables, or bucket.
No deployment was made. Before deploying or attaching to the existing stack,
the Cloud owner must confirm:

1. The existing Transactions table has the composite key and `ByCreatedAt`
   GSI required above, or approve adding the GSI.
2. The exact API Gateway integration/event format, JWT authorizer behavior,
   table and bucket names, Lambda names, and `LOG_GROUPS` values.
3. Whether a public S3 read policy for `products/*` is appropriate, or a CDN
   should serve product images instead.
4. The current frontend's reset-password button does not call the new backend
   route; frontend integration is still needed for that action.

These are environment integration tasks; do not copy credentials from the
Cloud architecture document into code or commit them.
